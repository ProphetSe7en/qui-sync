Export

Pull automations from your Qui instances and save them as versioned JSON files in your share-repo. Other users can subscribe to this repo via the Sync tab to import your rules.

How it works: 1. Expand an instance below to see its rules — exclude any you don't want to share. 2. Set the priority (sort order) for each rule — this is the order consumers will get them in. 3. Click Preview to see what would change, then Commit export to write files + auto-commit to git. 4. Use the Share-repo panel below to push to GitHub.

Safe for sharing: Your personal tracker lists are automatically replaced with placeholders. Rules using * (all trackers) keep the wildcard. Fields like enabled, dryRun, and notify are stripped — consumers set those themselves.

Backup & Restore

    
Full 1:1 backup of all automations per Qui instance — including trackers, enabled state, and everything else. No stripping, no placeholders.


    

      

        

          How it works:
          1. Click Backup now on an instance to snapshot all its automations.
          2. Backups are stored per instance with timestamp — each is a complete snapshot.
          3. To restore, expand the instance, select a backup, choose the target instance, and click Restore.
          4. Restore creates the rules in Qui exactly as they were — trackers, enabled state, intervals, everything.

Backup

      

      

        

          
          

          
          

          
          

          
          
        

        

          Schedule — how often the background worker snapshots every configured Qui instance. Off means manual backups only.

          Retention days — snapshots older than this are deleted after the next scheduled run. 0 = never expire by age.

          Keep last N — minimum number of snapshots kept per instance regardless of age. 0 = no minimum. When both are set, snapshots must satisfy both rules to be evicted (old AND outside the floor).

          Backups live in <repo>/../backups-full/. Full 1:1 copies including trackers — never pushed to GitHub when gitignored is on.

          New rules from the repo are never auto-applied.

Sync

    
Subscribe to share-repos and apply their rules to your Qui instances. Your local trackers and preferences are preserved on update.


    

      

        

          How it works:
          1. Add a subscription — point it at a git repo URL (public or private with SSH key / token).
          2. Click Pull to fetch the latest rules from the repo.
          3. Select which Qui instance to sync to, then click Plan to preview.
          4. For each rule, choose: Create new in Qui, Link to an existing rule, or Skip.
          5. Click Apply — new rules are created disabled. Linked rules are updated but your trackers, enabled state, and intervals are preserved.
          6. Toggle Auto on rules you want to keep in sync automatically whenever the repo updates.
