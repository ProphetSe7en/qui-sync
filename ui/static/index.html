Publish

Publish your Qui automations as a shareable collection. Push to GitHub so others can subscribe to your setup.

How it works: 1. Set the GitHub repository where your rules will live (top panel). 2. Add the Qui instances you want to share rules from. Expand any to fine-tune which rules get included. 3. Click Preview to see what would change, then Commit export to write files + auto-commit. 4. Use Push to GitHub to publish.

Safe for sharing: Your personal tracker lists are automatically replaced with placeholders. Rules using * (all trackers) keep the wildcard. Fields like enabled, dryRun, and notify are stripped — consumers set those themselves.
Where to publish

Connect a GitHub repository to publish your exported rules. Click Set up repository to begin. qui-sync uses one repository for all your published instances; per-instance overrides are planned for a future release.

Validating… Click validate to re-check the saved token

Create a fine-grained PAT on GitHub with Contents: Read+Write permission scoped to this repository. qui-sync stores the token at /config/git-push-token with mode 0600.

Backup & Restore

    
Full 1:1 snapshots of every automation in a Qui instance — trackers, enabled state, and everything else are preserved. Restore to the same instance or migrate to a different one.


    
    

      

        
Setup needed — connect to Qui first. Backups won't run until Qui is reachable.

        
      

    


    

      

        

          Backups protect your Qui automations so you can recover if something goes wrong.
          


          Schedules — set up once, run on their own. Give it a name, choose which instances to back up, and how often (every day at 03:00, twice a week, every 6 hours, etc.). Each fire makes a complete snapshot.
          

          Manual backup — snapshot one instance right now. Useful before a risky change.
          


          Restore works the same way in both cases: open History on a schedule, or expand an instance under Manual backup, then click Restore on the snapshot you want. Pick which Qui instance it lands in (originally backed up from, or a different one to migrate).

Auto-sync

      

      

        

          
          
        

        

          When enabled, qui-sync pulls all subscriptions on this interval and
          auto-applies changes to rules marked with the "Auto" checkbox in the
          Plan view. Rules without Auto (or explicitly skipped) are left alone —
          you apply or update them yourself.
          


          New rules from the maintainer are auto-created in your Qui as
          disabled. They show up in your automations list so you can review
          and turn them on when you're ready — qui-sync never enables a rule
          on its own.
          


          Auto-sync only runs for subscriptions that have an Apply target
          set (Edit subscription → Apply to which Qui instance). Subscriptions
          without a target are skipped silently.

Subscribe

    
Use Qui automations from someone else's collection. Your trackers and preferences stay yours — only the rule logic gets imported.


    
    

      

        
Setup needed — connect to Qui first. Subscribed rules can't be applied until Qui is reachable.

        
      

    


    

      

        

          Subscribe to someone else's automation collection so you can use their setup without copying each rule by hand.
          


          1. Add subscription — paste the repository URL, click Look up what's in this repo, then pick which folder (movies / tv / etc.) and which of your Qui instances should receive those rules. The instance choice is remembered so Plan + Apply use it automatically without asking again.
          

          2. Pull — fetches the latest rules from the repository. Click whenever you want to check for updates.
          

          3. Plan — shows what will happen for each rule (Create new, Update existing, or Skip). Two shortcuts speed this up:
          

            • Match by name — auto-links every repo rule to your existing Qui rule with the same name (case-insensitive). Use this when you've already got rules with matching names in Qui.
          

            • Create new for all — flips every rule to "create as new" if you'd rather start clean and reorganise after.
          

          You can override any individual decision in the table before applying.
          

          4. Apply — runs the planned changes. Your trackers, enabled state, and intervals stay yours — only the rule logic changes.
          

          5. Auto (optional) — tick the Auto checkbox on rules you want to track automatically. qui-sync will apply future repo updates to those rules in the background.
          


          New rules are always created paused. Enable them in Qui when you've checked the logic.
